# Coding Standards

## Core Principle

Code should be written for the programmer reading it five years from now, not the programmer writing it today.

## Standards

1. Readability beats cleverness.
2. Every class should represent something a coach would recognize.
3. Business logic should read like plain English.
4. Comments should explain why, not repeat what the code says.
5. Prefer clear loops over clever comprehensions when readability improves.
6. Avoid secret utility libraries and mystery helpers.
7. Archive important coaching history instead of deleting it.
8. Keep each file focused on one responsibility.
9. Use simple, direct names.
10. Technology serves the coach.

## Engineering Motto

Simple code scales better than clever code.
